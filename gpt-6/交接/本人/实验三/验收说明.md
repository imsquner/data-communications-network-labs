# 实验三　交换机与路由器配置

本资料记录 2026-11-17 在同一台电脑的独立 GNS3 工程中进行的第 A 轮实跑。实验目的为验证子网和 VLAN 对连通性的影响，并用静态路由、RIPv2 和 OSPF 比较跨网段通信、路由收敛和恢复。按《实验3-v4.pdf》第四至六节实施。

## 实测结论

1. **交换、子网和 VLAN**。SW1–SW2 用两侧 Fa0/0 互连，各接两台 VPCS。四台 PC 在 `192.168.30.0/24` 时六组测试全通。仅将 PC4 改到 `192.168.32.22/24` 后，其他三台之间仍通，涉及 PC4 的三组均失败。同一 `/24` 划为两个 `/25` 后，PC1、PC3 为一组，PC2、PC4 为一组，组内两组通，组间四组失败。恢复到同一 `/24` 后，Fa0/0 和 Fa0/1 划入 VLAN 200，Fa0/2 划入 VLAN 300。仅 PC1 至 PC3 跨交换机探测成功。交换机互连口是 VLAN 200 access 口，VLAN 300 流量没有跨交换机的路径。
2. **静态路由**。直连基线完成 9 项探测。单配 R1 时，从 PC1 到 R2 的 `202.103.2.2` 及对端 PC 均超时，R2 路由表缺少通往 `202.103.1.0/24` 的回程。两边补齐后，11 项探测均通。R1 的下一跳为 `202.103.2.2`，R2 的下一跳为 `202.103.2.1`，双方显示 `S [1/0]`。回程原因由两台路由表核对得到。
3. **RIPv2**。启用 `version 2`、`no auto-summary` 并宣告直连网段后，R1 学到 `192.168.1.0/24`，R2 学到 `202.103.1.0/24`，双方均显示 `R [120/1]`。在两台路由器暂停时删除互联，再恢复仿真。从 17:49:18 删链到 17:54:04 首次轮询确认双方撤路，主机墙钟间隔 286 秒，断链探测超时。按原步骤暂停并添加回原端口后，热重连在观测窗口内未恢复学习。本轮在同一工程中保留重连后的连线，重启节点并恢复原有 IP 和 RIPv2 配置，双方重新收到对端更新并恢复路由。18:02:46 双向 ping 复测通过。时间均为 UTC+8。
4. **OSPF**。使用进程 1、Area 0，两台路由器互见 `FULL`，双方显示 `O [110/20]`，对端 PC 双向通。

`C` 为直连路由，`S` 为静态路由，`R` 为 RIP 学习项，`O` 为 OSPF 学习项。方括号内依次为管理距离、协议度量。实测 RIP 度量为 1 跳，OSPF 总成本为 20。

## 路由拓扑与配置

- R1 `Ethernet0/0 202.103.2.1/24`、`Ethernet0/1 202.103.1.1/24`。PC1 `202.103.1.2/24`，网关 `202.103.1.1`。
- R2 `Ethernet0/0 202.103.2.2/24`、`Ethernet0/1 192.168.1.1/24`。PC2 `192.168.1.2/24`，网关 `192.168.1.1`。
- R1 互联接口录入步骤

```text
enable
configure terminal
interface Ethernet0/0
ip address 202.103.2.1 255.255.255.0
no shutdown
end
show ip interface brief
show ip route
```

## 实验命令及检查点

- 交换项目先用 `no ip routing` 关闭三层路由，通过 VPCS 的 `ip 地址/前缀` 配置各阶段地址，使用 `show ip` 和 `ping` 检查。IOS 的 `vlan database` 创建 VLAN 200、300，接口下的 `switchport mode access` 和 `switchport access vlan` 设置接入口归属。使用 `show vlan-switch brief` 和 `show interfaces FastEthernet0/0 switchport` 验证配置。
- 静态项目使用 `ip route 目标网段 掩码 下一跳` 手工配置。RIP 项目以 `router rip`、`version 2`、`no auto-summary`、`network` 宣告本端网段，用 `debug ip rip` 观察两侧在 Ethernet0/0 上收发更新并用 `undebug all` 关闭调试。OSPF 项目使用 `router ospf 1` 与 `network 网段 0.0.0.255 area 0`，通过 `show ip ospf neighbor` 验证邻接。
- RIP 和 OSPF 配置前，PC1 到 PC2 的基线均超时。两台路由器当时只有本侧局域网和互联段的直连路由，缺少远端局域网的往返路径。配置后重新执行 `show ip route` 检查远端前缀及下一跳，再测试双向 ping。
