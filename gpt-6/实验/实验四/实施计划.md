# 实验四 DHCP、Web 与电子邮件服务器实施计划

**状态**　方案待审。按《实验4-v4.pdf》第四至六节执行。现有来宾和本地资料已只读核对，待老板确认后开始配置、实跑和截图。

## 总体路线

1. 复用 VMware 的 Ubuntu Server 18.04.6 和 Windows XP Professional SP3，先核对隔离网、宿主访问、安装包来源与恢复点。
2. 按老师规定的顺序完成 ISC DHCP 源码编译、Apache 源码编译、Postfix 软件包安装。每项留服务器侧与客户端侧证据。
3. 同机独立跑本人轮和第二轮，关键结果出现时先截真图再推进。按要求编号逐项核验后交接。

## 0. 环境和两轮边界

- 已观察到两台 VMware 来宾进程，两份 VMX 指向同一私有 LAN Segment。实验二记录了 Ubuntu `192.168.77.2/24` 与 XP 的私有网双向通信。来宾当前 IP、网卡名、服务状态、宿主 Web 路径和公网邮件出口均在执行时实查。
- 保留私有 LAN 给 XP 和本机 ISC DHCP。Ubuntu 在该网的地址拟用 `192.168.77.2/24`。确认私有段没有其他 DHCP 应答，ISC DHCP 只监听此接口。XP 使用私有接口进行 DHCP 全新申请，无默认路由的隔离段不下发网关。
- Windows 宿主访问 Apache 优先让 Ubuntu 额外接入现有 VMnet1，使用核对后空闲的静态地址。实验二记录的宿主地址为 `192.168.37.1/24`，VMware DHCP 曾在 VMnet1 应答，所以 Apache 验证和 XP 的 ISC DHCP 验证使用不同接口。VMnet1 当前不可用时，验证既有 NAT 网的宿主至来宾路径，再选择实际可达的 Ubuntu 地址。安装包和 SMTP 出口优先仅由 Ubuntu 走已有 NAT，按需启用，核对没有开启转发。保留 XP 在私有网。
- 执行前归档本轮要改的 VMX、临时网卡映射、Netplan、服务配置与服务状态，留可恢复副本并检查磁盘余量。先用一个真实窗口样张走通保存、无鼠标检查、打开原图三个步骤。保存虚拟机系统版本及网络实测。宿主使用现有 Windows 11，报告按实际环境填写。
- 两轮串行，Ubuntu 共享已校验的源码压缩包、缓存和工具链。独立源码目录、配置、租约文件、编译安装日志、站点、邮件主题和截图。本人 DHCP 池拟为 `192.168.77.21–192.168.77.49`，第二轮拟为 `192.168.77.61–192.168.77.89`。两轮均在发现地址无冲突后启用。每轮开始清空本轮专用新租约文件并释放 XP 上轮租约，保留上轮副本，重新观察到 Discover 才开始验收。两轮共用一台宿主机，如实记录来源。

**E01**　VMware 或实际来宾窗口。Ubuntu 系统版本、私有接口和静态地址可读。  
**E02**　XP 系统版本、私有网卡配置及基线，图注注明这是配置前或起始状态。

## 1. DHCP 源码编译及 XP 验证

- [ ] 核对官方源码和完整性。课程配置辅助材料以 ISC DHCP 4.3.1 为示例。优先使用能验证来源的同版本源码，若缺失或不兼容，采用 ISC 的 4.4.3-P1 官方源码并记录版本差异和构建方式。依赖可从软件包获得，服务器本体保留源码构建证据。
- [ ] 在各轮构建目录执行 `./configure`、`make`、安装步骤。核对绝对安装路径、实际二进制和版本，以该二进制做配置检查，避免系统中已有同名服务抢占端口。
- [ ] 在本轮配置中声明 `192.168.77.0/24` 和本轮地址池。检查 `.1–.10` 均在动态范围外，`.0` 和 `.255` 分别为网络和广播地址。默认和最大租期设为 3600 秒。使用独立 `dhcpd.leases`，显式指定私有接口。检查进程、配置日志和 DHCP 报文的 Server Identifier。
- [ ] 在 XP 启用自动获取 IPv4，执行 `ipconfig /release`、`ipconfig /renew` 和 `ipconfig /all`。在 Ubuntu 私有接口开始抓包后再触发申请，记录 Discover、Offer、Request、ACK。以事务 ID 和客户端标识关联四帧，核对 ACK 的分配地址、掩码、服务器标识和 3600 秒 Lease Time。XP 端地址与 ACK 和服务端租约三方一致后判定通过。另验证 XP 到服务器可达。

**D01**　Ubuntu 实际终端，源码构建命令与成功输出、安装程序路径和版本。需要时分图。  
**D02**　实际配置与 `dhcpd -t` 检查，能读出地址池、子网和 3600 秒。  
**D03**　Ubuntu 私有网监听和对应 DHCP 日志或租约记录。  
**D04**　XP 命令窗口，释放、续租及 `ipconfig /all` 的 DHCP Server、地址和租期。  
**D05**　Wireshark 实际打开本轮包，DORA 列表与 ACK 字段。看不全时分两图。

## 2. Apache 源码编译及宿主机访问

- [ ] 使用 Apache 2.4 官方发布源码，记录版本及来源校验。根据 Ubuntu 现状核查 C 工具链及 Apache 版本所需的 APR、APR-util、PCRE 依赖。保留 `./configure`、`make`、安装记录与 `httpd -V` 输出。确认宿主浏览器将访问这一套编译产物。
- [ ] 配置本轮独立 `DocumentRoot`、匹配的 `<Directory>` 与 `ServerName`。本人轮拟用 `web-a.lab4.test`，第二轮拟用 `web-b.lab4.test`。两轮各写两个不同内容的文件，例如 `welcome.htm` 和 `status.html`，页面带轮次标识。按实测地址准备宿主侧名称映射，优先使用可还原的局部方式。如需证明默认页，再设置并验证 `DirectoryIndex`。
- [ ] 先验证 Ubuntu 端配置和相应监听，再在 Windows 宿主浏览器单独打开两个后缀的 URL。浏览器地址栏、不同正文与同一轮访问日志一一对应。以实际请求、HTTP 200 和站点标识验收。另记录修改前后根目录和名称、重载命令、域名如何解析到宿主可达接口。思考题附路径与域名修改的实际步骤。

**W01**　源码编译、安装成功及 `httpd -V`，必要时分图。  
**W02**　`DocumentRoot`、`ServerName`、目录权限、配置测试和监听。  
**W03**　Windows 宿主浏览器访问 `.htm`，地址和页面内容同框。  
**W04**　Windows 宿主浏览器访问 `.html`，地址和页面内容同框。  
**W05**　设定域名命中本轮网站。若 W03、W04 已显示该域名，可按证据索引共用对应原图，并附请求与 HTTP 200 的访问日志截图。

## 3. Postfix 软件包安装及邮件收发

- [ ] 先确认 Ubuntu 软件包源及所需出口，保留 `apt-get` 安装输出、安装版本、`dpkg-query` 和 `postfix check`。按两轮记录不同主题和唯一标识，配置有效的 `myhostname`、`myorigin`、`mydestination`、`inet_interfaces`、`mynetworks` 及需要的 `relayhost`。仅启用实际使用的接口和中继，口令、授权码和私有邮件不进入截图或共同交接包。
- [ ] 先以两个实验本地邮箱走一次投递与回复，核对队列 ID、投递记录、Mailbox 收件和回复的主题。用这条链同时验证软件包安装和本地投递路径。
- [ ] 指导书另要求发到自己的常用邮箱并回复。先检测 Ubuntu 的 DNS、出站 SMTP 连接和可用的回信路径。优先使用已授权的 SMTP 提交中继和 TLS，确认提供方的发件身份限制、目标邮箱及发送授权后才发真实测试邮件。本人和第二轮分别产生自己的投递记录。即使复用测试账号，也以不同主题、Message-ID 和 Queue ID 核对两轮。
- [ ] 按“Postfix 已提交 → 对方常用邮箱看到原信 → 从该邮箱回复 → 指定回复端收到”验收。优先收回实验服务器本地邮箱。若由服务商托管接收，需要区分只在托管邮箱可见与通过已授权的接收链进入 Ubuntu。记录收件时间、主题、必要的头字段和对应日志。报告思考题按实际路由说明回复为什么收到或未收到。
- [ ] 若公网 SMTP、邮箱授权或外部回信入口不可用，保存实际连接测试或 `postqueue`、`mail.log` 的具体结果，继续完成本地邮件链和其余两个项目。外发、外部收信、回复回到服务器分别记实测状态。到达需要用户补齐的路径时，一次集中列出具体缺项。

**M01**　实际 `apt-get` 安装过程、软件包和版本。  
**M02**　脱敏后的生效配置、检查命令及服务监听。  
**M03**　本地投递与回复的实际终端或邮箱窗口，配合 Queue ID。  
**M04**　外发窗口或 Postfix 队列日志，能追踪唯一主题与队列 ID。  
**M05**　常用邮箱实际入站页面，显示本轮原信的主题与时间。  
**M06**　回复及回复到达的真实窗口，可分为发送和最终收到两图。若外部条件欠缺，记录实测故障及对应截图，M05 或 M06 保留待验状态。

## 4. 报告截图闭环和归档

- [ ] 开跑前在两轮各自的索引中登记 E01–M06 的目标窗口、关键字段和预期结果。每次关键状态出现时按“截图 → 打开原图 → 同原始日志、帧号或队列项对照 → 通过后继续”执行。短时状态先拍下来再释放、重载或清队列。遇截断、串轮或鼠标，保留现场状态重拍，环境已推进时按原参数复跑。
- [ ] 报告图为 VMware/XP/Ubuntu 实际窗口、Wireshark、Windows 宿主浏览器和实际邮箱界面。常规处理限于裁边或隐私遮挡，并保留可核对的原始材料。发生异常也拍真实窗口。每张图登记轮次、阶段、采集时间、应用、操作、必须可读的字段、原始日志或报文引用及拟用图题。
- [ ] 阶段通过须同时具备实测结果和相应可读截图。验收逐张打开图，检查鼠标指针、裁切、清晰度、标题和阶段一致性，避免用计数替代覆盖。将图按实际尺寸试排到模板同宽的 Word 页面或等宽预览，确认字段缩小后仍可读。失败项明确追溯原因、截图状态和待补条件。
- [ ] Ubuntu 和 XP 配置改动前后做差异核对。两轮结束后停临时服务、抓包和调试，按记录还原临时网络、映射及可逆配置。确认所需来宾和宿主正常状态。
- [ ] 归档到 `gpt-6/交接/本人/实验四` 和 `gpt-6/交接/室友/实验四`。各自包含 `验收说明.md`、`截图/截图索引.md`、`实测/`、`配置/`，如有复跑程序则附 `脚本/`。校验可打开的文件、索引链接、各轮独立实测来源与 SHA-256。共享素材只记录来源和版本。
- [ ] 逐项补齐指导书的三个问答。解释实际使用的 `ls`、`cd`、`cp`、`rm`、`sudo`、`apt-get`、`tar`、`make`、`ip` 及服务检查命令。对比源码构建的可配置性、依赖及更新成本与软件包的依赖管理、安装和版本限制。按实际配置回答网站根目录与域名，按真实投递路径回答回信结果。后续沿用学生实验报告模板的预习、过程记录、结果与讨论结构。

## 执行收口

确认后按 **环境及截图试拍 → 本人轮 DHCP/Web/Postfix → 第二轮 DHCP/Web/Postfix → 逐图与原始证据核验 → 恢复环境与双目录交接** 运行。三种服务分别对照配置、执行结果和客户端表现。最终验收看两套说明与截图索引，以及邮件各个外部步骤的实测状态。合并 Word 作为四个实验验收后的下一阶段。
