## 接续任务

1. **恢复环境和执行通道。** 按原计划核对 VMX 备份、私有 LAN 和 NAT，启动原 Ubuntu 与 XP。本地控制台验证 `netlab` 一次登录和 `sudo`。若已有凭据无效，记录实际错误，由老板决定如何恢复来宾账号。查看 `netplan generate` 的错误定位，备份损坏 YAML，修复 NAT 对应接口并保持私有静态地址 `192.168.77.2/24`。验证重启后 NAT 获取有效地址、DNS 和软件源可达。确认现有 SSH 状态，按需安装 OpenSSH，优先宿主通过 VMnet8 直接连接实际地址，核验对端身份。检查 2222 转发归属，确认为本实验遗留后纳入收尾。原机与工作副本使用相同地址时保持单机上线。
2. **DHCP 两轮实测。** 将已校验的 ISC DHCP 4.3.1 源包传到来宾，若遇兼容错误才改用已经校验的 4.4.3-P1。分别按原计划两组地址池编译运行，服务仅监听私有网，租期 3600 秒。两轮分别核对 XP 实际租约、Ubuntu 租约记录、Wireshark DORA 和 ACK 字段。E01/E02 核对是否可复用，变化则重拍；补 D01–D05。
3. **Apache 两轮实测。** 编译已校验的 Apache 2.4.71，使用各轮独立站点内容核对根目录和域名。Windows 宿主浏览器实际打开各轮的 `.htm` 与 `.html`，按访问日志匹配 HTTP 200。补 W01–W05。
4. **Postfix 两轮实测。** 走软件包安装，先验本地投递。Foxmail 客户端认证曾通过，正式运行时从 Ubuntu 使用已有授权验证 SMTP；用每轮独立主题从 Postfix 发往指定校邮，回复至 Foxmail 后仅按对应主题或邮件标识取回测试信并落地到 Ubuntu 实验邮箱。核验 Postfix 队列 ID、校邮原信、Foxmail 回复、Ubuntu 本地邮件四段。开通、登录或送达失败时留原始证据及对应状态。补 M01–M06。
5. **验收和恢复。** 关键状态先留真实原图，再与命令输出、报文或队列记录对应。逐张打开确认字段、鼠标、裁切和模板宽度下的可读性。两轮独立完成并交付到 `gpt-6/交接/本人/实验四` 和 `gpt-6/交接/室友/实验四`。校验截图索引、日志和 SHA-256，收尾关闭临时服务与操作入口，按恢复点核对 VM 网络及运行状态。凭据文件和认证画面保留在私有管理范围，交接清单逐项排查。

## 执行顺序

原 VM 启动和账号验证 → NAT 与 SSH 稳定性检查 → 第一轮 DHCP、Apache、Postfix → 第二轮从对应基线复跑 → 实拍核验、双目录交接与环境恢复。阶段以配置、实际输出和证据三者匹配作为通过条件。
