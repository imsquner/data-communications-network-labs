# 实验三 交换机、路由器的配置

**状态**　老板已确认并授权执行。2026-11-17 两轮实跑已归档。热重连及重启后的恢复差异见 [本人验收](../../交接/本人/实验三/验收说明.md) 和 [第二轮验收](../../交接/室友/实验三/验收说明.md)。

## 总体路线

1. 验证本机 GNS3、Dynamips、VPCS 与 Cisco 3640 的实际端口和交换能力。
2. 先搭双交换机四主机，再用双路由器双主机分别执行静态路由、RIPv2 和 OSPF。
3. 在同一环境分两轮实跑。交接目录分别使用 `gpt-6/交接/本人/实验三/` 和 `gpt-6/交接/室友/实验三/`。每轮保存自己的项目、配置、日志和无鼠标指针截图。

## 要求与实施

### 0. 环境预检

现有 Cisco 3640 IOS 12.4(25d) 已在 Dynamips 中启动，两台设备的 NM-4E 链路已有连通烟测记录。实验三先用单台 3640 验证 EtherSwitch 模块 `NM-16ESW`、IOS 识别的实际接口名、VLAN 配置与二层转发，再验证 VPCS 控制台及 GNS3 本地连接。路由项目使用 NM-4E，以匹配指导书的 `Ethernet0/0`、`Ethernet0/1`。如果交换模块端口显示为 `Fa1/x` 等编号，按实际位置逐一映射指导书中 `f0/x`，在拓扑图同时注明用途。 [GNS3 Dynamips 镜像与 EtherSwitch 模块说明](https://docs.gns3.com/docs/emulators/cisco-ios-images-for-dynamips)

### 1. 交换、子网和 VLAN

在 GNS3 用两台 Cisco 3640 配合 EtherSwitch 端口，改交换机图标并执行 `no ip routing`。按指导书接线，两台 SW 以逻辑口 `f0/0` 互连。SW1 的 `f0/1`、`f0/2` 分别接 PC1、PC2，SW2 的对应口分别接 PC3、PC4。逐阶段留 IP、配置、端口和连通矩阵。

1. 同一私有 `/24`，四台 PC 验证同交换机与跨交换机连通。
2. 仅把 PC4 改到另一个私有 `/24`，验证 PC4 与其余主机的隔离及其余主机的连通。
3. 在原 `/24` 内划两个 `/25`，PC1、PC3 为一组，PC2、PC4 为另一组。每组横跨两台交换机，验证组内连通、组间隔离。
4. 四台 PC 回到同一私有 `/24`，按指导书将两台 SW 的逻辑 `f0/0`、`f0/1` 放入 VLAN 200，`f0/2` 放入 VLAN 300。指导书图中互联口 `f0/0` 属于 VLAN 200，因此预期 PC1 ↔ PC3 跨交换机可通，PC2 ↔ PC4 即使同属 VLAN 300 也因交换机间链路不承载该 VLAN 而不通。跨 VLAN 的对照同样应不通。以实测结果和端口配置验收。

两轮唯一的实验参数差异放在此处的私有地址。拟用本人 `192.168.30.0/24`、室友 `192.168.31.0/24`。各轮按其自己的 `/24`、异网段、`/25` 及 VLAN 状态采集原始结果。

### 2. 静态路由

按指导书固定地址建立 PC1—R1—R2—PC2，接口和 PC 地址均使用 `/24`。

- R1 `e0/0 202.103.2.1`、`e0/1 202.103.1.1`。PC1 为 `202.103.1.2`，网关 `202.103.1.1`。
- R2 `e0/0 202.103.2.2`、`e0/1 192.168.1.1`。PC2 为 `192.168.1.2`，网关 `192.168.1.1`。指导书重复标了 R1 并在 PC2 网关处多了一个点，以上按拓扑和后续配置段校正。

依次验证三个状态。

1. **直连基线**。两台路由器执行 `show ip interface brief` 和 `show ip route`，核对直连项。完成指导书列出的 PC 对 PC、PC 对同侧路由器两个端口、R1 和 R2 互测对方两个端口。
2. **单边静态**。R1 添加 `ip route 192.168.1.0 255.255.255.0 202.103.2.2`。从 PC1 ping R2 的 `202.103.2.2`，对照两侧路由表解释往程与回程。预期请求可达 R2，R2 缺少回到 PC1 所在网段的路由。
3. **双边静态**。R2 添加 `ip route 202.103.1.0 255.255.255.0 202.103.2.1`。同一测试矩阵复测，留两侧 `S` 路由、下一跳与双向连通证据。

### 3. RIPv2 与断链恢复

从只含直连项的基线起跑，两台 3640 分别配置 RIPv2、`no auto-summary` 与各自的直连网段。记录两端的 `R` 路由、下一跳、跳数与 PC1↔PC2 的 ping。按指导书暂停仿真、删除 `e0/0` 之间的连接再恢复仿真。按时间戳保留路由表直到远端学习项撤除。随后暂停并重连，执行 `debug ip rip` 记录更新，核对路由重新出现与业务恢复，再关闭调试。观察时间以接口状态和 IOS 的实际计时器为准。

### 4. OSPF

从直连基线起跑，按指导书使用进程 1、Area 0，在两端宣告各自直连网段。保存邻居状态、双方 `O` 路由、下一跳及成本，验证两台 PC 双向贯通。报告说明直连阶段和建立邻接后的差异。

## 验收与交付

执行顺序为 **环境预检 → 交换与 VLAN → 静态路由 → RIPv2 → OSPF → 对照验收**。本人轮完成后，室友轮从基线复跑。静态、RIP、OSPF 各自从直连基线起跑，防止前一项目的路由表项掩盖当前结果。两轮均保留规定地址、VLAN 和协议参数。

- 每个关键状态留拓扑、完整命令日志、设备配置、对应截图和预期／实测结论。静态、RIP、OSPF 逐项解释 `C`、`S`、`R`、`O`、管理距离、度量及下一跳。
- 报告附 R1 `e0/0` 配置完整命令，包括进入特权模式、进入配置和接口、设 `202.103.2.1 255.255.255.0`、`no shutdown`、退出与核验。其余问答按阶段对应截图。
- 两套分别交付 GNS3 工程、配置、日志、截图、验收说明和 SHA-256。使用同一个已存在的 IOS 镜像路径。离线查阅可直接打开图片、日志和说明。
